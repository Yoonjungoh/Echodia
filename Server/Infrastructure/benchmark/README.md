# Isolated game benchmark

Launch the game with the single argument `--qa-benchmark`. Launch the same login release with the same argument. The game binds IPv4 loopback TCP 17777. The release defaults remain the public game listener on 7777 and the private login listener on 8443. Use the same client machine and SSH local forward to the same game host in both runs. Validate the public game certificate against its actual SAN through the tunnel.

Set `ECHODIA_QA_RUN` to a run identifier of 1–24 ASCII letters or digits and `ECHODIA_DB_CONNECTION_DPAPI_FILE` to the host-local protected SQL connection. Both game and login verify that the selected catalog is exactly `EchodiaPerf_<run>`. Clear inherited `DB_CONNECTION_STRING` for these processes. Network SQL connections require verified TLS. A SQL connection using the exact shared-memory source `lpc:(local)\SQLEXPRESS` can use local shared memory without transport encryption. The change is limited to this benchmark mode. Prepare both empty databases with identical schema, account hashes, character IDs and inventory state, using SQL principals granted access only to their respective QA catalogs.

Use a separate cache credential in `ECHODIA_REDIS_CONNECTION_DPAPI_FILE`. The game uses one Redis set named `EchodiaPerf:<run>:loggedIn`. The private Linux cache role can load an additional named user, `echodiaperf`, from the administrator-owned file `C:\ProgramData\EchodiaRedis\benchmark-acl`. The file consists of the run identifier, a single space, the SHA-256 verifier of the independently generated credential, and an LF terminator. The Redis ACL confines all key commands for this user to the single QA set. It cannot administer Redis. A dedicated local cache instance may use an equivalent ACL. Before a run, the game binary's `--qa-clear-login-state` command validates the protected connection's QA catalog and deletes exactly its QA membership key. Stop clients and clear the membership key before withdrawing the QA user and restarting the cache role. Preserve the original data and backups. Restore the game/login services' previous states and startup settings.

Both topologies use the same game binary, client protocol and Kestrel mutual TLS. The physical colocation comparison can also change SQL transport, cache engine, total resources, certificate endpoints and I/O path. Record those factors, CPU counts, warm-up, workload, sample counts and which timing intervals include SSH forwarding. Interpret results as topology measurements, not a measurement of IOCP, CPU scheduling or TLS overhead in isolation.
